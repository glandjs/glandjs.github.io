## Why Gland?

Gland separates *what* your application does from *how* it is transported. A controller
receives an interaction and emits a domain event. A channel subscribes to that event
and performs the side effect. A broker connects the two to a real protocol.

That single idea produces a codebase where business logic can be tested without an
HTTP server, where the same domain code runs over more than one transport, and where
adding a new endpoint never means rewriting a service.
