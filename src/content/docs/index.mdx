<section class="home-section home-section--flow">
  <div class="home-section__heading">
    <span class="home-section__eyebrow">How it fits together</span>
    <h2>One request, four clear responsibilities</h2>
    <p>Every request follows the same path. Each step has a single job, so you always know where a behavior lives and what to replace when it changes.</p>
  </div>

  <ol class="home-flow">
    <li class="home-flow__step">
      <span class="home-flow__index">01</span>
      <strong>Controller</strong>
      <p>Receives the context, expresses intent and replies. It performs no side effects.</p>
      <code>ctx.call('db:product:all')</code>
    </li>
    <li class="home-flow__step">
      <span class="home-flow__index">02</span>
      <strong>Typed event</strong>
      <p>The contract between the two sides. A renamed event or payload is a compile error.</p>
      <code>EventTypes</code>
    </li>
    <li class="home-flow__step">
      <span class="home-flow__index">03</span>
      <strong>Channel</strong>
      <p>Owns the side effect: persistence, audit logs, notifications. Easy to fake in tests.</p>
      <code>@Channel('db')</code>
    </li>
    <li class="home-flow__step">
      <span class="home-flow__index">04</span>
      <strong>Broker</strong>
      <p>Carries the transport. Swap HTTP for another protocol without touching the domain.</p>
      <code>ExpressBroker</code>
    </li>
  </ol>
</section>
