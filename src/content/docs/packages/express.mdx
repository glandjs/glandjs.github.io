`@glandjs/express` binds your controllers and channels to a real
[Express 5](https://expressjs.com) application. It is the adapter most people start
with, and the reference for how the contract maps onto a framework that is not built
for promises.

```bash
pnpm add @glandjs/core @glandjs/common @glandjs/events @glandjs/http @glandjs/express express reflect-metadata
```

<Aside type="note" title="This page is a summary">
  The generated reference is [mirrored from the repository](/reference/http/adapters/express)
  on every build, so the table below never disagrees with the source.
</Aside>

## Attaching it

```ts
import { GlandFactory } from '@glandjs/core'
import { Controller, Module } from '@glandjs/common'
import { Get } from '@glandjs/http'
import { ExpressBroker, type ExpressContext } from '@glandjs/express'

@Controller('/products')
export class ProductController {
  @Get('/:id')
  async find(ctx: ExpressContext) {
    return { product: await ctx.call('db:product:find', { id: ctx.params.id }) }
  }
}

@Module({ controllers: [ProductController] })
export class AppModule {}

const { app, shutdown } = await GlandFactory.create(AppModule)
const http = app.connectTo(ExpressBroker, { poweredBy: false })

http.bodyParser({ json: true, urlencoded: { extended: true } })
http.listen(3000)
await http.ready()
```

## Exports

| Symbol | Description |
| --- | --- |
| `ExpressBroker<TEvents>` | The broker you pass to `connectTo()`. |
| `ExpressContext<TEvents>` | The context your handlers receive. |
| `ExpressCore<TEvents>` | The application object `connectTo()` returns. |
| `ExpressAdapter<TEvents>` | The transport implementation of `HttpServerAdapter`. |

Route decorators are **not** exported from here — they come from `@glandjs/http`, so a
controller never depends on the transport.

## The application surface

`connectTo()` returns the full [`HttpCore`](/packages/http#httpcore) surface, backed by
a real Express application. Reach the raw app through `http.instance` when you need
something Express-specific.

```ts
http.use(async (ctx, next) => {
  const started = Date.now()
  await next()
  console.log(`${ctx.method} ${ctx.path} ${Date.now() - started}ms`)
})

http.useRaw(compression())                 // framework middleware, unmolested
http.useStaticAssets('public')
http.setGlobalPrefix('/api')
http.enableCors({ origin: 'https://example.com', credentials: true })

http.listen(3000, { host: '0.0.0.0' })
```

Routes outside a controller work too, which is handy for a health check:

```ts
http.get('/ping', (ctx) => ctx.send('pong'))
```

## The one caveat: `next()` is a hand-off

Express's `next()` does not return a promise, so `await next()` resolves as soon as
Express moves on — a downstream `throw` never reaches an upstream `catch`. Every other
adapter gives you a real onion.

| | `await next()` waits | upstream `catch` sees a downstream throw |
| --- | --- | --- |
| `@glandjs/express` | **no** | **no** |
| `@glandjs/fastify` | yes | yes |
| `@glandjs/koa` | yes | yes |
| `@glandjs/hono` | yes | yes |
| `@glandjs/node` | yes | yes |

Three ways to live with it: do the work after the response rather than after `next()`,
move the recovery downstream into the error handler, or measure on
`HttpEvent.RequestEnd`. [Middleware](/reference/http/guides/middleware#the-express-caveat)
covers all three.

## What Express does better

Express is the most complete of the five out of the box, which is why it is often the
right first choice:

- `useRaw()` works, so `compression()`, `helmet()`, `cookie-parser()` and friends mount
  normally.
- Signed cookies work when `cookie-parser` is mounted.
- Views are built in: `setViewEngine()` and `setBaseViewsDir()` are real.
- Static file serving is built in.
- Every extended verb works, including `MKWORKSPACE` and `UPDATE`.

## What it cannot do

- **Multipart.** `bodyParser({ multipart })` throws at configuration time. Use `multer`
  through `useRaw()`, or pick another adapter.
- **`poweredBy: false`** removes `X-Powered-By`, which Express sets itself; Koa has no
  header to remove and ignores the option.
- **A single catch-all route.** `http.all('*')` works, but Express's own `app.use` order
  still decides what a request sees first.

  The same application on every transport is `examples/<adapter>/hello-world.ts` in the
  repository: the controller, the channel, the module and the middleware are
  byte-for-byte identical and only the import and `connectTo()` change.
</Aside>
